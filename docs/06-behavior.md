# 6. 動きを読み取る

見た目は設計図とリソースから写せます。けれども、「返信したときの件名」「引用の形」「削除したあと次にどれを選ぶか」といった**動き**は、どこか 1 か所にまとまっていません。次の 4 つを手がかりに、1 つずつ突き止めました。

1. **文字列表**: メッセージや状態バーの文言は、ほぼすべて MUI の文字列表にあります。文言があれば、その動きがあることもわかります。
2. **アクセラレーター表**: キー操作（4 章）。
3. **オプションの既定値表**: 入れた直後の設定の値（後述）。
4. **コード**: 文字列の番号やオプションの名前を使っている関数を Ghidra で読み、いつ、どう使うかを確かめます。

## オプションの既定値表

`msmail.dll` の中に、オプションの名前と既定値を並べた表がありました（ファイル位置 0x3e0e0〜0x42640）。

- 1 件は 36 バイトで、`番号、型（0x13 = DWORD）、種別（全体・メール・ニュース・迷惑メールなど）、名前へのポインター、既定値、……、最小値、最大値` の順です。[観察]
- 見つけ方: オプションの名前（`Poll For Mail` などの文字列）を探し、その文字列を指しているポインターをさかのぼりました。

この表から読めた既定値の例です。

| 名前 | 既定値 | 意味 |
|---|---|---|
| `Poll For Mail` | 600000 | 10 分ごとに新着を確認する |
| `Use US Reply Headers` | 1 | 返信の引用ヘッダーを英語にする |
| `Indent Char` | 0x3E（`>`） | 引用の印の文字 |
| `Indent Reply Text`（メール） | 0 | メールでは引用に印を付けない |
| `Reply To Messages In Original Format` | 1 | 受け取った形式（テキスト / HTML）で返信する |
| `Reply At End` | 0 | 返信は本文の先頭に書く |

## 例: 返信の件名

返信の件名を作る関数は、`msmail.dll` の `FUN_101dff23` でした。[観察]

- `Use US Reply Headers` が 1（既定）なら、頭は「Re: 」（転送は「Fw: 」）です。0 なら文字列表の「RE:」（空白なし）と「FW: 」を使います。
- 元の件名の先頭 6 文字に既知の頭（`Re: `、`Fw: `、`RE:`、`FW: `。大文字小文字は区別しない）があれば取り除いてから付け直します（`FUN_101cd93d`）。「Re: Re: 」にはなりません。
- 「Fwd: 」は知らない頭として、そのまま残ります。

**実データでの確認**: 解析に使った PC の保存庫（5 章）で、送信済みフォルダーの件名を数えました。返信の頭はすべて「Re: 」でした。この PC の利用者が既定の設定のまま使っていたことの裏付けになります。

## 例: 返信の引用ヘッダー

引用の前に付く「From: … Sent: …」の部分は、`mailcomm.dll` の `FUN_100723c0` が組み立てていました。[観察]

- **HTML の返信**: 空の行のあとに、背景色 `#F5F5F5` の囲みを置き、その中に「太字のラベル + 値」を 1 行ずつ並べます。全体は `font: 10pt Meiryo UI` の `DIV` で包みます。「-----Original Message-----」の行は**付きません**。元の本文は字下げせずに、そのあとに続きます。
- **テキストの返信**: 1 行目が「-----Original Message-----」、続いて「ラベル 値」の行、最後に空の行です。本文の行頭に `>` は付けません（上の既定値表のとおり）。
- **ラベル**: 英語ヘッダーのときは `From:`、`Sent:`、`To:`、`Cc:`、`Subject:` です。ラベルの表は 0x10073e74 にあります。値が空の行は出しません。
- **日付**: `GetDateFormat` と `GetTimeFormat` で作ります。英語ヘッダーのときは、書式のフラグが変わります（`FUN_10073faf`）。

## 例: 作成のフォント

作成の窓の既定のフォントは、`msmail.dll` の `FUN_101d4121` で決まります。フォントが設定されていないときに文字列表から読むのは「Meiryo」と「10」でした。[観察]

最初は、画面のほかの部分と同じ「Meiryo UI」だと推定していました。コードを読んで初めて、違うとわかりました。動きの推定はこのように外れることがあるので、各項目に [観察] か [推定] かを付けて管理しました。

## 例: 新着の知らせ

- タスク バーのボタンに重ねるアイコンは、`msmail.dll` の `FUN_10048e86` が出しています（ソースのパスに `mailnews\shell\taskbar.cpp` という文字列が残っていました）。
- 新着の通知は、`FUN_100f5cec`（`mailnews\spooler\toastmanager.cpp`）です。1 通のとき、同じ人から複数のとき、複数の人からのときで、文言が分かれています。

## 一覧にまとめる

調べた動きは、分野ごと（一覧のキー操作、スレッドと開封、返信と転送、作成と送信、送受信と通知、フォルダーと削除、検索と状態バー）に表にしました。

- 1 行に、本物の動き（根拠の番号付き）、作り直した側の今の動き、判定（同じ / 違う / 無い / 作れないので灰色）を書きます。
- 使う人が気づく度合い（毎日、ときどき、ほとんど気づかない）も付け、気づきやすいものから直しました。

表は Microsoft の文字列を多く含むので、このリポジトリには入れていません。

## わかったこと: 「動き」の多くはデータにある

返信の頭が「Re: 」なのも、引用に `>` が付かないのも、プログラムに直接書かれているのではなく、**既定値表の値で切り替わる**作りでした。既定値表を見つけてから、動きの調査が一気に進みました。
