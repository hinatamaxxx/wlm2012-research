# 8. わかっていないこと

推定のまま残っているもの、確かめきれていないものの一覧です。どれも、本物を実際に動かして見比べれば決着がつきます。この解析では本物を動かしていません。

## 画面の設計図・リソース

- **シートの規則の優先順位**: 当てはまる規則のうち「最初の 1 つ」が使われることは確かめました。並び順の決め方（条件の細かさの順か、追加した順か）は推定です。
- **要素の種類の名前**（リボン）: タブ、グループ、ボタンなどの種類の番号の意味は、並びと中身から当てたものです。
- **既定の配色**: 既定で配色の色がかかっているかどうかは、`msmail.dll` 側の設定をたどりきれていません。
- **使われていない命令**: UIB の命令のうち、手元の 29 個のファイルで一度も使われていないもの（ジャンプ、呼び出しなど）は、意味をコードからだけ読んでいます。
- **4006 のフラグ 0x2000**: 意味がわかっていません。

## 動き

- **返信ヘッダーの日付**: `GetDateFormat` に渡すフラグの意味は推定です。Windows の版によって、日付の書き方（「November 2」か「November 02」か）が変わる可能性があります。
- **テキストの返信での住所の書き方**: 「名前 <アドレス>」と、複数人の区切り「; 」は推定です。
- **新着の通知の出し方**: 本物は送り主ごとに通知を出すようですが、作り直した側では 1 回にまとめています。
- **タスク バーの新着の印を消す条件**: 「新着がすべて既読になったとき」と推定しています。
- **送受信の進行状況の窓**: 文言は文字列表にありますが、いつ・どう出るかは調べきれていません。
- **ダイアログのアイコンと既定のボタン**: 一部は推定です。

## 確かめ方

本物の Windows Live メール 2012 が動く PC があれば、次の方法で確かめられます。

1. 本物と作り直した側で、同じ大きさの窓の画面写真を撮って並べる。
2. 返信・転送したメールを自分あてに送り、生のメール（ヘッダーと本文の HTML）を比べる。
3. オプションの既定値は、新しく作った Windows のユーザーで本物を起動し、設定を変える前の状態で確かめる。
