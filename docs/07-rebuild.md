# 7. 作り直しの方針

解析の目的は、Windows Live メール 2012 を、**見た目と動きはそのまま、中身は今の部品**で作り直すことでした。作り直したアプリは家族の PC だけで使い、配布はしていません。ここでは、どう組み立てたかをまとめます。

## 組み立て

| 部分 | 使ったもの |
|---|---|
| 窓とシステムとのやり取り | C#（.NET Framework 4.8）、WinForms |
| 画面 | WebView2（Edge）の上の React |
| メールの送受信 | MailKit（IMAP・POP3・SMTP） |
| 古いデータの取り込み | `.eml` の読み込み + ESE の既読情報（5 章） |
| インストールと自動更新 | Velopack |

画面を HTML で作ったのは、DirectUI の設計図の値（寸法・色・状態ごとの規則）を CSS にそのまま移せるからです。2 章のシートの規則は、CSS のセレクターと宣言にほぼ 1 対 1 で置き換えられました。

## 見た目を合わせる

- 寸法、色、余白は、設計図とリソースから読んだ値をそのまま使いました。目で見て合わせた値はありません。
- 画像は、リソースから取り出したものを番号のまま使いました。
- 拡大率 150%・200% の画面でも本物と同じに見えるか、画面写真を撮って比べました。

## 使えない機能は灰色で残す

カレンダーの予定、アドレス帳、ニュースグループ、フィードなどは、作り直した側では使えません。それでも、ボタンやメニューを**消さずに灰色（無効）にして同じ場所に置きました**。

長く使ってきた人にとっては、「ボタンがいつもの場所にあること」が大事です。項目が消えると、ほかのボタンの位置までずれてしまいます。カレンダーは表示だけ残し、予定の作成だけを灰色にしました。

## 中身は今のものにする

- **通信**: MailKit で今の TLS を使います。
- **表示**: メールの HTML は、スクリプトを動かさない枠（sandbox）の中で、WebView2 で表示します。WebView2 は Edge と一緒に自動で更新されます。
- **パスワード**: Windows の DPAPI で、その利用者のアカウントでしか読めないように暗号化して保存します。
- **新着**: IMAP IDLE で、届いたメールを数秒で受け取ります（元は 10 分ごとの確認でした）。
- **添付ファイル**: 実行ファイル（.exe など）は開かせません。

## サーバーには手を出さない

乗り換えのあいだ、元のアプリと同じサーバーのメールを見ることになります。そこで、サーバーに対する操作は次の 2 つだけにしました。

- 既読の印（IMAP の `\Seen`）を合わせる。
- 送ったメールの控えを、サーバーの送信済みフォルダーに入れる。

削除・移動・コピーは、サーバーでは一切しません。アプリの中で「削除」しても、消えるのは手元の写しだけです。テストでは、テスト用のサーバーに DELE や EXPUNGE などの命令が一度も届かないことを確かめています。

## 本物と違えたところ

使う人の希望で、あえて本物と違えたところもあります。

- メッセージを閲覧ウィンドウに表示したら、すぐ既読にする（本物は、設定した時間だけ表示し続けると既読になる。既定値の表では 1 で、単位は秒と推定）。
- スレッドは最初から開いた状態にする。オプション画面の表示も、この動きに合わせました。

## 試し方

- **画面の試験**: GitHub Actions の Windows の実行環境で、アプリを実際に起動します。WebView2 の DevTools プロトコル経由で、クリックやキー入力をします。テスト用の IMAP・POP3・SMTP サーバーを Node.js で立て、受信、返信、削除、オフラインなど 50 以上の手順を通します。
- **画面だけの確認**: C# の部分を JavaScript の偽物に置き換え、普通のブラウザーで画面を開けるようにしました。Linux でも、ヘッドレスの Chrome で画面を見て確かめられます。

## つまずいたこと

- **タスク バーの別アイコン**: アプリが自分で名乗る ID（AppUserModelID）と、インストーラーが作ったショートカットの ID が違っていたため、タスク バーにピン留めしたアイコンとは別のアイコンで起動していました。インストーラー（Velopack）が付ける ID にそろえて直りました。
- **名前の変更**: 内部の ID を変えるとき、更新の通り道（チャンネル）も変えました。古い版が新しい版を自分の更新と取り違えないようにするためです。新しい版は初回起動のときに古い版のデータを写し、全部写せたことを照合してから、古い版を消します。
